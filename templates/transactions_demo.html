ACID Properties

  • Atomicity: All operations in a transaction succeed or all fail
  • Consistency: Database remains in a valid state
  • Isolation: Concurrent transactions don't interfere with each other
  • Durability: Committed changes are permanent

Isolation Levels Explained:

  • READ UNCOMMITTED: Can read uncommitted changes (dirty reads)
  • READ COMMITTED: Only reads committed data (default in PostgreSQL)
  • REPEATABLE READ: Same data throughout transaction
  • SERIALIZABLE: Strongest isolation, prevents all anomalies

Why We Use READ COMMITTED:

For a fitness tracker, READ COMMITTED is appropriate because:

  • Users typically work on their own data
  • Prevents dirty reads while allowing good concurrency
  • Workout transfers are rare and can handle slight delays
